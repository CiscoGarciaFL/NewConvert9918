# Conversion performance baseline

This baseline measures the portable Phase 3 conversion core. It is intended to
guide later background-work and optimization decisions; it is not a CI timing
threshold.

## Method

- Date: 2026-09-16
- Host: Windows kernel `10.0.22621`, 4 logical processors (virtual machine)
- Compiler: MinGW GCC 13.1.0, `Release`
- Input: deterministic 256x192 RGB gradient generated by
  `benchmark_core_conversion`
- Settings: current defaults, including Atkinson error diffusion and 1% maximum
  color shift
- Sampling: one process, one conversion per mode, in the order shown

Run an equivalent local measurement with:

```powershell
cmake --build <release-build-directory> --target benchmark_core_conversion
<release-build-directory>\benchmark_core_conversion.exe
```

## 2026-09-16 result

| Mode | Wall time | Estimated owned buffers |
| --- | ---: | ---: |
| Bitmap 9918A | 12,570.48 ms | 1,536,000 bytes |
| Greyscale Bitmap 9918A | 6,809.27 ms | 1,536,000 bytes |
| Black-and-White Bitmap 9918A | 245.87 ms | 1,529,856 bytes |
| Bitmap Color Only 9918A | 149.89 ms | 1,536,000 bytes |
| Multicolor 9918 | 98.78 ms | 345,600 bytes |
| Dual Multicolor 9918 | 1,608.56 ms | 347,136 bytes |
| Half Multicolor 9918A | 17,767.41 ms | 1,538,048 bytes |
| Paletted Bitmap F18A | 10,453.56 ms | 1,536,077 bytes |
| Scanline Palette Bitmap F18A | 10,325.09 ms | 1,550,784 bytes |

The memory estimate counts the prepared RGB source, RGB preview, indexed work
image, target tables, retained palette data, and the error-diffusion buffer
when used. It deliberately excludes allocator metadata, stack frames, temporary
palette-selection allocations, Qt/runtime libraries, and process overhead, so
it is not a resident-set-size claim.

## Interpretation

Memory is bounded and modest: the largest explicitly owned conversion buffers
are under 1.5 MiB. CPU cost is the constraint. Exhaustive two-color/pattern
search makes the full-color Graphics II, Half Multicolor, and F18A modes too
slow for synchronous UI execution on this VM. The Qt integration must debounce
changes, execute conversions off the UI thread, cancel superseded requests,
and publish only the newest generation. Later optimization should preserve
golden bytes and use this benchmark to compare changes.
