# New Convert 9918 v0.1.0-beta.3

This corrective prerelease supersedes `v0.1.0-beta.1` and
`v0.1.0-beta.2`. Do not install the Debian packages from either earlier beta.

## Debian isolation correction

The earlier Debian packages reused the AppImage deployment tree as the system
filesystem. They could install `/usr/bin/qt.conf`, `/usr/plugins`, `/usr/qml`,
and bundled libraries directly into global locations. On Kubuntu,
`/usr/bin/qt.conf` redirected the Qt 5 SDDM greeter to the application's Qt 6
plugins, leaving SDDM active but preventing the graphical login screen from
starting after reboot.

The beta.3 Debian package instead installs its complete private runtime under:

```text
/opt/newconvert9918
```

Only application launchers, the desktop entry, icons, and package
documentation are placed in conventional `/usr` locations. Application-local
`qt.conf`, libraries, plugins, and QML modules stay under the private prefix and
cannot change plugin discovery for unrelated Qt applications.

The release gate now rejects the dangerous global paths, verifies a positive
Debian `Installed-Size`, launches the installed GUI and CLI, removes the
package, and confirms that its private runtime and launchers are gone.

## Downloads

- Windows 10 version 1809 or newer, x64: use the `Setup.exe` installer or the
  `Portable.zip` archive.
- Linux x64 with glibc 2.34 or newer: use the AppImage for a portable launch or
  the beta.3 Debian package on Ubuntu 22.04 and compatible systems.
- macOS 13 or newer: use the `arm64` DMG on Apple Silicon or the `x86_64` DMG
  on Intel Macs.
- `SHA256SUMS.txt` contains the SHA-256 digest for every binary package.

All packages include the runtime files they need. Qt, CMake, a compiler, and a
developer environment are not required.

## Debian installation and replacement

First remove either unsafe earlier beta if it is installed:

```shell
sudo apt remove newconvert9918
```

Install beta.3 with:

```shell
chmod 0644 newconvert9918_0.1.0-beta.3_amd64.deb
sudo apt install ./newconvert9918_0.1.0-beta.3_amd64.deb
```

If APT reports that the download was performed unsandboxed because `_apt`
could not access the archive, the private parent directory containing the
download is the usual cause. It is an informational notice when installation
otherwise completes, not evidence that this package installed outside its
private runtime. Mode `0644` on the archive alone cannot help when `_apt`
cannot traverse a parent directory.

To avoid the notice without weakening home-directory or APT permissions, copy
the archive to an accessible temporary path for installation:

```shell
install -m 0644 ./newconvert9918_0.1.0-beta.3_amd64.deb /tmp/newconvert9918.deb
sudo apt install /tmp/newconvert9918.deb
rm /tmp/newconvert9918.deb
```

Do not disable APT sandboxing, make the home directory world-readable, change
the archive to mode `0777`, or change its owner to `_apt`.

After installation, the private runtime is under `/opt/newconvert9918`; no
global `/usr/bin/qt.conf`, `/usr/plugins`, or `/usr/qml` path is created.

### KDE Plasma application icon

The Debian package installs its desktop entry in `/usr/share/applications` and
matching PNG and SVG icons in the standard hicolor theme under
`/usr/share/icons`. If Plasma was already running during installation, its
per-user KService cache may temporarily retain a generic application icon even
though those package files and the system icon cache are correct. Logging out
and back in rebuilds the session state. On Plasma 5, the user can instead run
this from Konsole without `sudo`, then reopen the application menu:

```shell
kbuildsycoca5 --noincremental
```

Use `kbuildsycoca6 --noincremental` on Plasma 6. A Debian maintainer script
must not attempt this operation: package configuration runs as root, cannot
correctly update every logged-in user's cache, and should not add a KDE-only
side effect to an otherwise desktop-neutral package.

## Other corrections retained from beta.2

- The Windows desktop executable uses the Windows GUI subsystem and does not
  open a console window. The separate CLI remains a console application.
- Package publication verifies Windows executable subsystems, Debian archive
  mode, exact release assets, DMG integrity, and SHA-256 checksums.
- Linux X11 is covered by automated testing. Kubuntu under Wayland remains a
  tested preview environment for the application, with Debian host-integrity
  verification strengthened in this release.

## Preview signing and trust prompts

These beta packages are not signed with a publicly trusted Windows or Apple
Developer ID certificate. The macOS application has only an ad-hoc signature.
Verify the downloaded filename and its SHA-256 checksum before authorizing a
platform trust prompt.

Linux AppImage users should verify the checksum, make the file executable, and
launch it:

```shell
chmod +x NewConvert9918-0.1.0-beta.3-Linux-x86_64.AppImage
./NewConvert9918-0.1.0-beta.3-Linux-x86_64.AppImage
```

## Verify checksums

On Linux or macOS, place `SHA256SUMS.txt` beside the downloads and run:

```shell
sha256sum --check SHA256SUMS.txt
```

On Windows PowerShell:

```powershell
Get-FileHash .\NewConvert9918-0.1.0-beta.3-Windows-x64-Setup.exe -Algorithm SHA256
```

## Known limitations

- Packages are unsigned previews and may trigger platform trust warnings.
- Update discovery and automatic installation are not included.
- Linux targets x64 systems with glibc 2.34 or newer. Other Wayland
  distributions and compositors remain provisional.
- Character and Sprite workspace data is saved in recipes, but CLI conversion
  of those editor-specific recipe types is deferred.

Please report package, launch, conversion, export, or compatibility problems at
<https://github.com/CiscoGarciaFL/NewConvert9918/issues> and include the asset
name, operating-system version, and relevant diagnostics.
